# Reading combat mechanics records

Follow a unit’s skill ID into `skills`, its `abilityId` into `abilities`, then the chosen level’s ordered `effects` into the `effects` table. Each row retains its source ID. The observations below use game version `0.41.1:uE5ua8JhTzqQZSsu57R4Iw`, revision `659681e`. Read the publication manifest for the version of a downloaded record. [Source snapshot](https://github.com/swgoh-utils/gamedata/tree/659681e348027c206a59886e5466a82c8c8f344b) · [Comlink collection relationships](https://github.com/swgoh-utils/swgoh-comlink/wiki/Game-Data)

## Skills and ability levels

| Field | Interpretation |
| --- | --- |
| `skills[id].levels` | Level 1 is the base. Successive source `skill.tier` entries describe the upgrades to levels 2 onward, including their recipe, requirements and tier-specific Zeta and Omicron flags. `omicronMode` must be read with the applicable upgrade flag. |
| `abilities[id].levels` | Level 1 uses the root ability. The first `ability.tier` is level 2. Each record preserves its own effect sequence. Luthen’s `uniqueskill_LUTHENRAEL02` has seven upgrades and an associated ability with only a base definition. Higher-level effect lists for that ability are unknown. |
| `roles` | Taken from the unit’s basic, special, leader and unique reference slots. The engine’s activated/passive/crew hardware/reinforcement classification is separately available as `abilityType`. An empty role list means no inspected slot designated a role. |
| `baseCooldown`, `cooldownMaxOverride` | Source initial maximum and per-upgrade maximum. The selected level’s `cooldown` uses the source value and `cooldownType` identifies turn- or speed-based cooldowns. Executor’s `specialability_capitalexecutor03` progresses from 30 to 20. A zero maximum occurs on zero-base abilities. A future negative value, or positive-base/zero override, yields null for the selected cooldown and preserves the raw value. |

The inspected ability cooldowns are all nonnegative. Unit reference fields can separately carry `requiredSkillTier: -1`. No inheritance rule for ability levels or cooldowns follows from that field. Tech’s unique provides an independent upgrade check. The game table flags its eighth level as a Zeta and Capital Games identifies the unique as a Zeta in the kit reveal. ## Damage and context

For `DAMAGE`, `damageType` decodes the source mitigation class. `ATTACK_DAMAGE` maps to physical, `ABILITY_POWER` to special and `UNMITIGABLE` retains its literal meaning. `applyType` describes how an effect is applied. A physical damage effect can have `UNAVOIDABLE` application. The operand source and restrictions remain in `parameters` and `targeting`. Unknown enum values retain their numeric code. [Source enums](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/enums.json)

For Darth Vader, follow `specialskill_VADER01` → `specialability_vader01` → level 8. The non-raid-boss damage entry has base multiplier 2.032, context multiplier 0.5 and variance 0.05. Its corresponding raid-boss branch has context multiplier 1. The source encodes these coefficients in ten-thousandths. Its localized level description corroborates the 50% and 100% context values. Each branch refers to index 1, the preceding debuff-count operation. Keep the sequence, context indexes, repeated references and each target predicate together. These numbers alone give no battle damage outcome. [Ability definitions](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/ability.json) · [Effect operands](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/effect.json.br) · [English localization](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/Loc_ENG_US.txt.json.br)

The normalizer retains `multiplierAmountDecimal`, `contextMultiplierDecimal`, `additiveAmountDecimal` and `resultVarianceDecimal`. Only `DAMAGE` receives the three verified coefficient projections in `damageCoefficients`. Raw additive values can be integer strings. Target stat bounds keep their source scale and endpoint inclusivity. Timing, stacking, variance distribution, defense, and tie-breaking require further evidence before combat calculations.

## Targeting, replacement and status

- Effects carry selector, side, health and deployment states. Optional exclusion flags, class and alignment filters, category versus required-category groups, tag predicates and stat bounds retain their source structure. `abilities[id].allyTargetingRuleId` links to the named `targetingRules` row. Trigger and expiration conditions retain type, value and priority. [Targeting rules](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/battleTargetingRule.json)
- `effects[id].replaceTableId` links to `effectReplacements`. These rows retain each source tag and the replacement effect ID in source order. The snapshot has 10 mappings for Brutus and 36 for Hondo. Inline summon effects can override a global effect with the same ID. The embedded definition preserves the actual variant. [Source tables](https://github.com/swgoh-utils/gamedata/blob/659681e348027c206a59886e5466a82c8c8f344b/table.json)
- `mechanics` provides evidence-backed search terms. Examples include `revive` for `REVIVE_UNIT`, `instant_defeat` for `DESTROY`, and turn-meter change for `RECOVER` acting on `SPEED_FILL`. A bonus move earns `assist` when its targeting explicitly excludes the `no_assist` tag. Counterattack rating changes and prevention carry different terms. Conditions, affected tags, and raw operations remain available for other cases.
- `statusEffects` groups effect IDs by the exact persistent localization key. Where the text has a formatted heading, the heading supplies the name. Unlabelled keys keep a null name. Buff and debuff classifications require an explicit source tag or force parameter on a variant. For example, ordinary and undispellable Target Lock share a heading and have different per-effect tags. A missing classification or mechanic search term represents limited evidence.
